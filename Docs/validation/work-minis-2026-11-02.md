## 패키지

[최종 패키지·린트 검사](https://github.com/kws07042/office-v2/actions/runs/41374301915)는 성공했다. 커밋 01cfd7700674433cc866f78c3f95aeffc8c3e9d0에서 공식 SDK로 새 컴파일·패키징했다. 게임 소스가 직전 검증 실행과 같으므로 이 마지막 CI 실행에서는 이야기 검사를 재실행하지 않고 린트와 패키지 검사만 실행했다. push 전후의 Source/game 변경 여부를 확인하며, 비교 기준 커밋을 가져올 수 없으면 보수적으로 이야기 검사를 실행한다.

- 파일: afterwork_script_prototype-0.35.0-work-minis-win.zip
- 크기: 43,519,556바이트, ZIP 내 1,570개 파일.
- SHA-256: 75f35c0e9c38a12f95c1d6516814730aadab6f0fc43c4b3ffc755dff06269ed7
- ZIP CRC 통과, Windows EXE와 game/work_minis.rpyc 포함.
- 테스트 대본·개발용 renpy_agent·저장 데이터·서명 개인키·Source/art 후보 제외.
- 게임 개발용 .rpy 소스 제외. 공식 SDK가 기본 제공하는 renpy/common/*.rpy는 런타임 구성으로 유지.
- 기존 Windows/game 컴파일 파일은 사용하지 않음.
- [비공개 빌드 산출물](https://github.com/kws07042/office-v2/actions/runs/41374301915/artifacts/13110093221)은 2026-11-09 만료 예정. 영구 릴리스가 아니다.
- Windows EXE를 직접 실행하지는 않았다. 빌드와 구성 검사를 Windows 실행 확인으로 해석하지 않는다.

## 발견한 실패와 수정

1. 최초 공통부 저장 검사는 C08 다음 선택지가 곧바로 리아 R01이라고 가정해 실패했다. 새 W_COORD01에 실제로 답한 뒤 R01에 도달하는지 검사하고, C08 저장을 복원하면 업무 사건 완료 기록도 사라지는지 추가했다. 업무·저장 자체의 최초 25사례는 통과했다. [최초 실행](https://github.com/kws07042/office-v2/actions/runs/41370886710)
2. 57사례가 통과한 뒤 패키징 명령이 상대 경로 launcher를 저장소에서 찾아 실패했다. 실행 대본 오류는 아니었다. 실제 SDK/launcher의 절대 경로로 수정하고 실패할 때도 build.log를 출력하도록 바꿨다. [실패 기록](https://github.com/kws07042/office-v2/actions/runs/41371769606)

3. SDK 경로 수정 뒤 Windows ZIP 생성은 성공했지만, ‘.rpy가 하나도 없어야 한다’는 과도한 검사 때문에 공식 엔진의 renpy/common/*.rpy까지 실패 처리했다. ZIP을 직접 열어 해당 57개 파일이 공식 런타임 경로이며, 새 업무 스크립트는 있고 금지한 개발/저장 파일은 없음을 확인했다. 검사를 게임 개발 소스와 공식 엔진 소스로 구분하도록 수정한 뒤 최종 패키지 검사가 통과했다. [생성 성공·검사 실패 기록](https://github.com/kws07042/office-v2/actions/runs/41373163484)

## 확인 범위

Linux에서 Ren’Py 엔진과 화면 선택을 실행했다. Windows EXE를 Windows에서 직접 실행한 결과는 아니다. 새 게임·테스트용 새 저장·구버전 변수 상태 모의 검사를 사용했으며, 모든 과거 실행판의 실제 저장 파일 호환을 보증하지 않는다. 새 삽입 지점을 이미 지난 저장 파일에 과거 사건을 소급 삽입하지 않는다. 재미·읽기 시간·최종 시청각 품질은 자동 검사로 평가하지 않았다. 기존 Windows 폴더의 0.34.1 실행판은 이번 새 대본을 포함하지 않는다.
