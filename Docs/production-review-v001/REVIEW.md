1. **개별 마스터**: 타이틀 오른쪽 앞 리아의 얼굴·녹색/청록 눈·금발 포니테일·큰 남색 리본·칼라/접힌 짧은 소매·남색 사원증을 직접 참조. 중립 전신1개, PNG 알파. 가려진 신발/등판은 승인 질문으로 남긴다. 완료 기준은 얼굴·손·의상·알파·기준선·작은 화면 가독성이다.
2. **R07 일반CG**: `ria_r05_r08.rpy:247`, 비 오는 카페 앞 우산 전달. 전경 손과 우산, 차양 물방울, 두 성인 간 거리 중심 중경. 사복 디자인은 제작 전 확정한다. 실내 도입 CG와 별개다. 기존 우산 v005는 삭제됐으며 당시 대조 기록만 남는다. 새 그림은 타이틀v002를 직접 참조한다.
3. **R11 일반CG**: `ria_r09_r12.rpy:263`, 첫 파스타 선택에서만 리아가 면을 건지고 도현이 소스를 젓는다. 셋째 선택도 파스타지만 담당이 반대이므로 그 경로에는 쓰지 않는다. 서로 다른 작은 숟가락·냄비·두 사람의 손 역할을 구분한다. 덮밥 분기에는 이 그림을 사용하지 않는다.
4. **R07 이벤트 세트**: 도입의 조용한 차 대화와 수줍은 표정까지 REVIEW. 본장면3슬롯은 장면 생략 상태여서 HOLD. 기본 구도를 억지로 확정하거나 노골적 묘사를 생성하지 않는다. 서비스/모델 정책과 사용자 승인 후 허용 범위에서 명세를 확정한다.

프롬프트 공통 초안: “현재 승인된 타이틀 v002의 오른쪽 앞 성인 강리아를 직접 참조한다. 얼굴·눈·금발 포니테일·큰 남색 리본·2D 선화·셀 명암을 유지한다. 장면의 승인 의상, 행동, 소품만 변경한다. 새 액세서리·도현 얼굴·확정하지 않은 텍스트를 추가하지 않는다. 16:9 구성, 손·핵심 소품이 하단 UI에 가려지지 않는 여백.” R07에는 우산/빗물, R11에는 승인된 파스타 동작을 추가하되 서로 혼합하지 않는다.

방식 비교는 **같은 비노골적 R07 브리프를 GPT/로컬/하이브리드 각1샘플**로 수행한다. 가중치는 얼굴35/화풍30/구도·손·소품25/수정편의10, 각 항목0~5점의 가중평균×20으로100점 환산한다. 시간·재시도·가격·최대VRAM을 기록한다. 현재 샘플3개 생성, 실측가격, GPU/품질 비교는 전부 미실행이다. 결과 없이 특정 방식을 최고라고 판정하지 않는다.

## 공식 스킬·도구 조사와 로컬 전략

OpenAI 공식 `openai/skills`의 `.system/skill-creator/SKILL.md`와 `references/openai_yaml.md`를 HTTPS로 읽고 기존 스킬4개를 재검토했다. 필요한 name/description과 사용 조건, 단순 디렉터리 구조를 유지했고, UI 메타데이터 `agents/openai.yaml`을4개 추가했다. 기존 스킬이므로 초기 템플릿 재생성은 건너뛰었다. 공식 quick_validate 프로그램을 설치/실행하지 않고 로컬 YAML 파싱·필수키·이름·UI 설명25~64자·기본프롬프트 스킬명 검사를 실행했다. 자동으로 스킬이 선택되는 실사용 품질은 별도 평가다.

RTX4060 8GB/RAM32GB용 **초기 실험 제안**: 배치1, SDXL급 정지 이미지768~1024 한 장, 참조 제어1개, 필요한 부위 인페인트, 단일 포즈 제어는 필요할 때만 추가, 메모리 부족 시 해상도/제어 수부터 낮추고 오프로딩 사용. 대형 영상/동시 다중 제어/즉시 LoRA 학습은 첫 검증에서 제외한다. 이 수치는 실제 사용자 PC에서 측정한 성능이 아니다. 모델 용량과 설치디스크/VRAM은 선택 모델의 실제 파일·옵션에 따라 달라지므로 설치 승인 전 모델 카드·라이선스·해시·예상디스크를 따로 제출한다. 상업 사용이 가능한 정확한 모델은 아직 확정하지 않았다.

권장 실험 순서는 GPT 비노골적 후보→필요한 영역만 로컬/수작업 수정→Krita 후처리→기술QA→시각QA→사용자승인→게임 연결이다. GPT는 지시/대화 편의, 로컬은 파일·재현 설정 관리, 하이브리드는 세부 수정 제어가 장점 후보이나 실제 시간/가격/일관성 우열은 샘플 비교 전 미검증이다. 권리 확보, 개인정보 업로드 경계와 서비스 정책은 각각 확인한다.

## 다음 결정과 출시 확인 범위

구도/의상 상세 승인, 본장면 미작성 범위, 새 전신의 가려진 부분은 실제 제작 전 결정이 필요하다. 주요 시나리오 수정·Ren’Py 구조 변경은 제안만 남겼다. GPT6 Luna/Sol 모델로 실제 전환하거나 별도 검토를 실행했다고 주장하지 않는다. Sol 심층 검토 후보는 서윤 구테스트 전환, O04와 갤러리/자동기록의 일관성, 독자 플레이테스트의 감정적 완성도, 화면1280→제작1920 연결이다.

실제 Windows 빌드/실행, Steam 요구사항 전체 검토, 저장/불러오기/롤백, 제안 출력308개 실제 생성, 외형별 Pass 판정, 최종 라이선스 패키징은 미실행이다. 공식 SDK 다운로드 차단이 해결되면 준비한 환경에서 네이티브 검사로 진행하되 오래된 suite의 기대값부터 별도 검토한다. `www.renpy.org` 허용은 현재 인스턴스에 적용되지 않았으며 설정 초안 저장만으로 다운로드/게임 실행이 성공한 것은 아니다.

## 재현 검증 명령

- `python3 -m unittest discover -s Source/tests -p 'test_*.py' -v`: 기존48개 통과.
- `python3 -m unittest discover -s Source/tools/tests -p 'test_*.py' -v`: 검사기8개 통과. 재현 소스는 `Source/tools/tests/test_image_assets.py`, `test_image_inventory.py`. 빈 디렉터리·명시적 누락 경로·메신저 사진 유무를 포함한다.
- `python3 Source/tools/check_image_assets.py`: 삭제 후 제작 참조 PNG1개 정상, 이벤트80경로 및 메신저1경로 미제공. JSON 결과는 이 폴더의 image-audit.json에 보관.
- `git -c core.whitespace=cr-at-eol diff --check`: 기존 RPY의 CRLF를 유지한 상태로 변경분 공백 검사 통과. RPY Python 블록과 새 이미지 조건식은 AST 구문 검사만 했으며 게임 코드는 실행하지 않았다. 삭제51/유지37 해시·현재 매니페스트·인용문34개·제작 합계 대조 결과는 [validation-summary.json](validation-summary.json)에 기록했다.
- 스킬4개의 YAML/이름/필수키/UI 메타데이터 검증과 CSV 행수/인용 위치 검증 통과. 공식 quick_validate 프로그램 실행 결과는 아님.
- 새로 작성한 스킬·도구·테스트·산출물에서 중국어/일본어 문자 혼입 없음. Python 도구에 네트워크 요청·외부 프로그램 실행 기능 없음. 전체 저장소의 보안 감사나 무감염 보증과는 다른 확인 범위다.
