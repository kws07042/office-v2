# 전체 파일 보안 검증 — 2026-11-02 (KST)

## 결론
검사한 저장소 스냅샷에서 정보탈취 악성코드의 증거를 발견하지 못했다. 현재 파일 전체와 접근 가능한 Git 과거 기록을 바이러스 검사했고, EXE/DLL 전부와 Python pyc 전부가 공식 SDK와 바이트 단위로 일치했다.

이는 사용자의 PC·계정 무감염, 과거 계정 탈취 원인 규명, 또는 모든 공격 가능성의 부재를 보증하지 않는다. 게임을 실행한 동적 분석과 완전한 소스/컴파일 결과의 의미 동등성 증명은 수행하지 않았다.

게임의 `Windows/afterwork_script_prototype.exe`는 공식 SDK의 `renpy.exe`와 같다. 파일 이름만 바뀐 정상 런처이며 SHA-256은 `8dabd499909d27f919ef1bb1bc863aba87e36d6e969b462471cc881653a374d0`이다. 나머지 EXE 4개, DLL 7개도 공식 SDK에 같은 바이트의 대응 파일이 있다. 공식 SDK와 같다는 것은 공급망 변조 지표를 줄여주지만 엔진/의존성에 알려지지 않은 취약점이 없다는 뜻은 아니다.

기존 검토에서 엔진 텍스트 250개도 공식 소스 태그와 Git blob SHA가 일치했다.

## Ren'Py 컴파일 파일 추가 확인
### 게임 고유 컴파일 파일 29개
rpyc의 슬롯을 압축 해제하고 pickle opcode를 비실행 구조 해석기로 읽었다. 대상 pickle의 GLOBAL/REDUCE/BUILD를 실제 import·함수 호출로 처리하지 않았다. 두 슬롯에서 추출한 Python 코드/표현식 2,806건 중 2,802건이 대응 Source/game 소스의 토큰열에서 확인되었다.

나머지 4건은 `office_phone.rpyc`에서 두 슬롯/참조에 반복된 두 종류의 화면 반복문 변수 분해문이었다.
- `value, caption = _sl2_i`
- `contact, name, initial = _sl2_i`

대응 소스 `office_phone.rpy`의 for 반복문(112·190행)과 공식 엔진 `renpy/sl2/slparser.py`의 864~873행에서 `_sl2_i`에 패턴을 대입하는 코드를 확인했다. 따라서 새로운 외부 명령이 아니라 공식 화면 파서가 생성하는 문장으로 분류했다.

`cream_ui.rpyc`의 HTTP 문자열은 SVG XML namespace였으며 외부 접속 코드가 아니다. 게임 컴파일 파일의 구조 검사에서 브라우저 인증정보 수집이나 명령 실행/외부 유출 구현을 발견하지 못했다. 브리지는 기존 소스와 동일한 코드 조각이 확인되었다.

이 비교는 코드 조각·표현식의 정적 대응 확인이다. 모든 Ren'Py 문장, 화면 AST, 제어 흐름에 대한 완전한 의미 동등성 증명은 아니다. 검사 결과를 새 클린 빌드의 대체물로 사용하지 않는다.

### 엔진 컴파일 파일
현재 엔진 rpyc/rpymc 중 공식 SDK와 전체 바이트가 다른 66개는 양쪽 슬롯의 Python 코드 조각과 전역 클래스 참조 목록을 비교했고, 모두 공식 SDK 대응 내용과 일치했다. 생성 메타데이터 등을 포함한 파일 전체가 동일하다고 주장하지 않는다.

구조 해석 실패로 표시된 오래된 rpymc 5개는 공식 SDK 파일과 전체 바이트가 동일했다. 이를 파서의 지원 범위 제한으로 기록하며 감염으로 분류하지 않았다. 현재/과거 `00iconbutton.rpyc`의 `store.icon.Icon` 참조도 공식 SDK 대응 참조와 일치했다.

Python pyc는 대상 코드를 실행하지 않고 marshal/dis로 정적으로 읽었다. 현재 839개 모두가 SDK 파일과 같으므로 커스텀 Python 바이트코드 변조는 발견하지 못했다.

## 인증정보 검색 결과의 분류
원본/과거 blob의 대표적인 비밀 형식 검색에서 개인키 PEM 표식 17건이 나왔다. 모두 공식 SDK와 전체 바이트가 같은 ecdsa/rsa 라이브러리의 PEM 처리 코드 또는 테스트 예제였다. 사용자의 실제 개인키 유출로 분류하지 않았다. 값 자체는 보고서나 로그에 출력하지 않았다.

이 검색은 모든 토큰 형식·암호화/난독화된 비밀을 식별하는 검사가 아니다.

파일 형식 검사는 이미지/폰트 파서의 모든 취약점 부재를 입증하지 않는다.

## 남아 있는 보안 개선
악성코드 발견과 별개로, 기존 제작 도구는 로컬 코드 실행과 설치본 쓰기 권한을 가진다. 일반 배포물에는 개발용 `renpy_agent.rpyc`가 남아 있으므로 다음 클린 빌드에서 소스와 컴파일본 모두 제외해야 한다. 세이브 서명 경고 유지, 인증키 제외, 출처 확인, 개발 환경 분리 지침도 계속 적용한다.

이번 PR은 현재 게임의 실행/컴파일 파일을 교체하거나 기존 저장 데이터를 수정하지 않는다. 개발자가 검토한 소스로 공식 SDK에서 새로 빌드하고 배포 해시를 남기는 후속 절차가 권장된다.
