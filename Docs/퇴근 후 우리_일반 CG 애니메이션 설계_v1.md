## 1. ‘그림을 움직인다’는 세 가지 방식

생활 공간 연결: 통합 기획서 v2.51 기준으로 히로인의 집은 공통 구도에 인물별 가구·소품·색을 다르게 구성한다. 일반 CG는 해당 집 변형의 가구 위치·취미 소품·조명을 참조하고 같은 공간의 기준을 유지한다. 카메라 높이·원근·인물 여백을 공통으로 관리하며 큰 색조만 바꾼 공간으로 완료하지 않는다. 인물별 집·CG·레이어는 아직 미제작이며 리아 이미지 작업은 재개하지 않는다.

음악 연결: 통합 기획서 v2.49의 사용자 확정 방향은 밝은 미연시풍의 피아노·기타·가벼운 리듬이다. 일반 CG는 해당 장면의 음악을 유지하고 감정·장소가 실제로 바뀔 때만 전환한다. 고백의 중요한 줄에서 빛·표정·음악을 모두 크게 움직이지 않으며 대사와 얼굴을 읽을 시간을 둔다. 실제 음악 파일·곡 수·음원 제작은 아직 미확정이다.

| 방식 | 실제로 만드는 것 | 잘 맞는 용도 | 제작상 차이 |
|---|---|---|---|
| 한 장의 그림 연출 | 줌·이동·페이드·색·빛 변화 | 모든 일반 CG의 등장과 분위기 | 그림의 눈·손·머리가 독립적으로 움직이는 것은 아님 |
| 레이어·차분 애니메이션 | 배경·인물·소품 분리, 눈·입·표정 차분, 작은 움직임 | 대표 4개의 감정 순간 | 분리된 그림과 가려진 부분을 준비하고 위치를 맞춰야 함 |
| 그림을 짧은 영상으로 생성 | 여러 프레임의 영상 파일 | 중요한 짧은 컷의 시험 | 생성 비용·형태 변화·루프 연결·영상 형식 검수 필요 |

**기본 제작 방식은 Ren’Py의 이미지 연출과 레이어·차분이다.** 영상 AI와 Live2D는 실제 시험 결과가 좋을 때 추가로 검토한다. 모든 그림을 영상으로 생성하는 방식을 기본 예산에 넣지 않는다.

## 2. 도구·플러그인의 역할

### Ren’Py ATL — 첫 번째로 사용할 기본 기능

Ren’Py에 내장된 애니메이션 언어다. 그림의 위치·확대·회전·불투명도 등을 시간에 따라 바꿀 수 있다. 이 기능 자체 때문에 별도의 유료 애니메이션 플러그인을 구매할 필요는 없다. [공식 ATL 문서](https://www.renpy.org/doc/html/transforms.html)

본작 적용: CG 등장 시 짧은 전환, 대화 시작의 느린 줌, 장소의 빛·전경·배경의 작은 이동. 움직임은 얼굴·대사 읽기를 방해하지 않는 범위로 제한한다. 모든 감정에 같은 흔들림을 반복하지 않는다.

### 이미지 레이어와 차분 — 대표 4개에 우선 적용

인물·배경·전경을 나누면 앞뒤 이동의 차이로 깊이를 줄 수 있다. 눈을 감은 차분과 표정 차분이 있으면 대사에 맞춰 전환할 수 있다. 이를 별도 그림으로 관리하거나 `layeredimage`로 구성한다. 생성형 도구가 만든 한 장의 그림을 자동으로 완전한 애니메이션 모델로 취급하지 않는다. [Ren’Py 공식 레이어 이미지 문서](https://www.renpy.org/doc/html/layeredimage.html)

처음에는 몸의 기준 레이어를 유지하고 눈·입·표정에 필요한 변형만 정렬한다. 기준 입상에서 표정을 파생해도 의상과 얼굴이 달라질 수 있으므로 실제 게임 크기에서 비교한다. 얼굴 조각의 경계·피부색·빛을 확인한다.

### Live2D Cubism FREE — 복잡한 변형을 위한 선택지

분리된 그림에 변형 구조를 만들고 표정·시선·머리·머리카락 움직임을 제어하는 외부 편집 도구다. Ren’Py는 Cubism 모델을 재생할 수 있지만 SDK 설치와 모델 제작이 필요하다. [Ren’Py 공식 Live2D 문서](https://www.renpy.org/doc/html/live2d.html)

Cubism FREE는 제한된 기능의 기본 모델·애니메이션을 만들 수 있다. 공식 비교표는 개인·소규모 기업의 상업 사용 조건을 설명한다. 편집기 조건과 게임에 사용하는 SDK의 조건은 실제 배포 방식에 맞춰 각각 확인한다. [Cubism FREE·PRO 공식 비교](https://www.live2d.com/en/cubism/comparison/)

본작에서는 처음부터 네 인물 전체를 Live2D로 리깅하지 않는다. 대표 한 장의 레이어·차분으로 원하는 움직임을 만들 수 있는지 먼저 확인한다. Live2D가 필요한 수준의 시선·머리 변형은 그 시험 이후 판단한다.

### Higgsfield — 연결된 영상 생성 플러그인 후보

이번 대화에서 실제 모델 카탈로그를 읽어 이미지 입력이 가능한 Seedance 2.0 Mini와 MiniMax Hailuo를 확인했다. 영상 생성은 실행하지 않았으며, 파일 업로드 없이 비용 견적만 요청했다.

| 시험 후보 | 조회한 설정 | 견적 |
|---|---|---:|
| Seedance 2.0 Mini | 5초·480p·음성 없음 | 2.5크레딧 |
| MiniMax Hailuo 2.3 Fast | 6초·768 설정 | 4크레딧 |

조회 시 일반 잔액은 2크레딧으로 두 예시의 견적에 부족하다. 별도 무료 모션제어 1회는 참조 영상이 필요한 특정 기능이며 일반 이미지→영상 생성 무료권으로 간주하지 않는다. 무료체험 무제한 생성은 활성 상태가 아니었다. 크레딧 견적은 실제 원화 비용이나 생성 품질을 보장하지 않는다.

이 후보들은 일반 CG의 짧은 동작 시험에만 비교한다. 본작의 그림체·얼굴·손·소품을 유지하는 능력은 아직 검증하지 않았으며 특정 모델이 항상 잘 맞는다고 추천하지 않는다. 추가 결제와 체험 활성화는 이번 조사에서 진행하지 않았다.

눈 깜빡임·표정·머리카락 움직임은 해당 레이어와 차분이 준비됐을 때 구현한다. 현재 리아 시안 한 장에 이 기능이 이미 들어 있다는 뜻은 아니다.

### 나머지 일반 CG의 기본 연출

18개 전체에 등장 전환과 필요할 때의 줌·이동·빛 효과를 적용한다. 한 장면마다 모든 효과를 동시에 쓰지 않는다. 대사의 중요한 순간에는 움직임을 멈추고 표정과 말을 보게 한다.

16:9 게임 화면의 하단 대사 영역을 고려해 얼굴·손·중요 소품을 배치한다. 같은 얼굴 근접 구도만 반복하지 않고 대화의 눈높이, 소품을 함께 보는 사선, 장소가 보이는 넓은 구도를 섞는다. 가까운 구도는 인물의 감정을 설명할 때 사용하고 신체 부위를 강조하는 연출은 이 일반 CG 목록의 목적이 아니다.

전체 그림의 2~4% 정도의 느린 줌과 작은 이동부터 시험한다. 이 수치는 자체 시작 가설이며 효과가 잘리는지·인물이 미끄러지는지·글을 읽기 어려운지에 따라 조정한다. 효과 강도를 줄이거나 정지 이미지를 사용하는 옵션을 제공한다.

## 5. 제작 파이프라인

**사건·대사 확정 → 구도 러프 → 기준 인물로 일반 CG 제작 → 레이어·차분 준비 → 움직임 연결 → 실제 화면 검수.**

대표 4개는 배경, 기준 인물, 얼굴 차분, 머리카락·소품의 필요한 부분을 구분한다. 움직여 드러나는 뒤쪽 영역도 그려져 있어야 한다. 레이어가 움직일 때 빈 구멍이 보이면 새 영상 AI로 덮기보다 해당 배경·가려진 영역을 수정한다.

영상 AI를 시험하는 경우에는 얼굴과 손의 형태, 물건의 개수·위치, 의상, 카메라, 마지막 프레임의 연결을 확인한다. 짧은 영상이 만들어졌다고 바로 자연스러운 반복 루프가 되는 것은 아니다. 실패한 컷을 무한 재생성하기보다 정지 그림과 엔진 연출로 돌아갈 수 있게 설계한다.

## 6. Ren’Py 구현 예시와 영상 형식

공식 ATL 문법에 따른 시작 예시다. 아래는 실제 프로젝트에 연결하거나 실행 검증한 코드가 아니다.

```renpy
transform cg_slow_push:
    subpixel True
    xalign 0.5
    yalign 0.5
    zoom 1.0
    linear 8.0 zoom 1.035

# 해당 CG 파일과 가상 화면 크기에 맞춰 위치·크기를 조정한다.
image cg_ria_confession = "images/cg_ria_confession.png"
show cg_ria_confession at cg_slow_push
```

영상 파일을 사용하는 경우 Ren’Py의 데스크톱 디코더가 지원하는 코덱·컨테이너로 준비한다. 공식 문서는 VP9 등의 코덱과 WebM 등을 설명하며, 일반 알파 영상은 직접 해석하지 않고 마스크 방식이 필요하다고 명시한다. AI 서비스의 MP4를 확장자만 바꿔 사용하는 방식으로 처리하지 않는다. [Ren’Py 공식 영상 문서](https://www.renpy.org/doc/html/movie.html)

일반 배경 포함 CG 영상은 우선 배경까지 포함한 하나의 영상으로 시험한다. 투명 영상 입상은 별도의 마스크·정렬·게임 화면 검증이 필요하다. 장면의 음성은 이미 검수한 한국어 음성과 연결하고 영상의 배경 소리가 대사를 덮지 않게 한다.

## 7. 검수와 현재 상태

- 대표 얼굴과 시선이 움직임 뒤에도 같은 인물로 유지되는가?
- 눈·입 차분의 경계와 몸·배경의 정렬이 보이지 않는가?
- 소품과 손, 머리카락이 다른 물체로 바뀌지 않는가?
- 반복 구간의 시작·끝에서 갑자기 튀지 않는가?
- 대사를 읽는 동안 효과가 시선을 계속 빼앗지 않는가?
- 정지 옵션·스킵·저장·회상에서도 장면과 음향이 이어지는가?
- 기본 연출 18개와 대표 레이어 4개의 작업량이 사건 95개의 일정 안에 들어가는가?

2026년 10월 13일 갱신: 리아 이미지는 사용자 제작본 대기다. 기존 저장소 원본·수정본·확대본은 현재 게임의 사용 대상에서 제외하고 리아 이미지·애니메이션 자산 작업을 중단한다. 기존 원본 연출 데모는 과거 시험 기록이며 새 리아 자산의 승인 자료가 아니다. 새 마스터·포즈·표정·레이어를 전달받아 확정한 뒤 파일을 연결하고 위치·전환·가장자리를 다시 검수한다. 일반 CG 18개의 기본 연출과 대표 4개의 레이어 애니메이션 목표는 유지하지만 현재 완성된 것으로 표시하지 않는다. 자산 대기 중에는 대본·호감도·기억 명세를 진행한다.
