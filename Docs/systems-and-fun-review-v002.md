# 필요한 시스템·재미 요소 검토 v002

2026-11-05. office-v2의 현행 대본·화면·상태 코드를 기준으로 검토했다. 아래 새 기능은 **제안**이며 이번 서윤 대본 개정에 몰래 추가하지 않았다. 재미의 개선 폭이나 플레이 시간은 실측하지 않았다.

## 이미 있는 것

- 네 개인 루트, 선택 일상 12개, 업무 방식 미니 사건 6개와 실제 선택 기억.
- 대화 기록·읽은 대사 스킵·자동 진행·글자 속도·메신저 연락처·답장·기록·사진 확대.
- 검토 브랜치의 관계 현황, 스토리 자동 기록/재진입, 이벤트 CG 감상·회상, 엔딩 기록 후보.
- 성인 이벤트에서 함께/귀가/대화 뒤 귀가와 의상 대안을 구분하는 상태.
- 같은 정보를 다시 입력하는 일정 관리나 반복 선물 시스템은 아직 없다.

따라서 ‘스킵 기능 추가’, ‘메신저 처음부터 개발’, ‘업무 미니게임 6개 신설’을 신규 재미 요소로 다시 제안하지 않는다. 이미 있는 분기·기억이 눈에 보이게 만드는 작업을 우선한다.

## 우선순위

|순서|제안|현재 근거|기대 효과|범위·비용|
|---|---|---|---|---|
|1|일반 행동 CG 표시·감상 연결|34장 목록은 제작 문서이며 현재 `pm.asset_catalog(event_cg_plan)` 감상 목록은 이벤트 자산 중심이다.|요리·조립·스케치 같은 행동이 실제 보상 장면으로 보임.|일반 CG manifest, 실제 파일 확인, 대본의 해당 가지에서만 표시, 표시한 것만 해금. 새 그림은 현재 제작 계획 사용.|
|2|‘다음 약속’ 카드|약속은 여러 `memory` 문자열과 메시지에 저장되지만 한눈에 모인 화면이 없다.|내가 정한 시간·장소가 다음 데이트로 이어지는 기대감. 서윤 일정도 자연스럽게 이해.|메신저 상단/기록 탭에 하나의 작은 카드. 확정/후보/다시 이야기할 일 구분. 달력 전체나 자유 시간표는 만들지 않음.|
|3|‘우리 기록집’ 페이지|도현의 사진·문장·취향 선택과 각자의 감상이 실제 대본에 있지만 화면은 주로 텍스트다.|플레이어의 선택이 이번 회차만의 결과물로 남음.|이미 남긴 문장·감상·방문 장소만 회차 저장에서 읽기. 각 루트 첫 페이지부터. 새 CG 강제 없이 기존 장소 그림 활용.|
|4|장면별 음악·작은 소리|options.rpy의 music/sound/voice가 모두 False이며 실제 음원은 별도 제작 대상이다.|고백·일상·갈등·해소가 그림만 바뀔 때보다 뚜렷해짐.|일상/설렘/긴장/해소의 소수 트랙과 컵·메시지 정도부터. 실제 파일 확보와 라이선스 확인 후 적용.|

개인적인 제작 추천은 **CG 연결 → 약속 카드 → 기록집 한 페이지**다. 이 세 가지는 현재 게임의 ‘함께 한 일이 기억된다’는 성격을 강화한다. RPG식 새 재화를 붙이지 않고도 선택의 결과를 보여 줄 수 있다.

## 출시 전에 필요한 기반

### 저장 화면 확장

현재 `screen file_slots`는 `range(1, 5)`로 수동 슬롯 네 개를 표시한다. 긴 네 루트와 선택을 비교하기에는 여유가 적고 날짜만으로 저장 장면을 구분해야 한다.

썸네일·현재 장면명·수동 페이지·자동/빠른 저장 페이지를 구분하는 UI를 권한다. 기존 1~4번 슬롯은 유지하고 새 페이지를 추가해 이전 저장을 가리지 않아야 한다. Ren’Py는 [FileScreenshot, FilePage 등 파일 화면 기능](https://www.renpy.org/doc/html/screen_actions.html#file-actions)을 제공한다. 새 저장 형식이나 개인 세이브 역직렬화 도구를 만들 필요는 없다.

### 엔진에서 실행하는 검토 브랜치 검사

브라우저 시안과 순수 모델 검사는 Ren’Py 화면 언어·레이아웃·실제 저장 호환성을 확인하지 못한다. 공식 SDK로 Lint → 서윤 초기 공개 → 고백 거절 → 두 관계 종료 → 세 친밀 선택 → 세 후일담 선택 → 저장/로드/롤백을 확인할 검토 브랜치 작업이 필요하다.

[Ren’Py 공식 자동 테스트](https://www.renpy.org/doc/html/testcases.html)는 선택·화면·입력 검증을 지원한다. 기존 `seoyun_checks`와 `progression_smoke`를 실제 엔진에서 실행한 기록을 남겨야 한다. 이번에는 네이티브 검사 정의만 수정했으며 실행 통과로 표시하지 않는다.

## 구현 시 지킬 데이터 원칙

- 확정한 약속만 ‘확정’으로 표시하고 상대의 제안이나 미래의 재논의와 구분한다.
- 소개를 생각해 본 선택을 아이와 만난 기록으로 만들지 않는다.
- 선택하지 않은 손잡기·요리·의상 CG를 다른 가지에서 보여주지 않는다.
- CG 파일이 없으면 감상 완료·회상 완료로 처리하지 않는다.
- 기록집은 이번 회차의 실제 기억을 사용한다. 다른 회차의 해금 이력을 현재 연인의 추억으로 합치지 않는다.
- 편의 기능과 공개/연락/접촉/소개 선택에 호감도 정답을 붙이지 않는다.
- 접근성 기능은 [Ren’Py의 기본 self-voicing/접근성 지원](https://www.renpy.org/doc/html/self_voicing.html)을 확인한 뒤 화면의 대체 설명과 초점을 보완한다.

## 지금은 보류할 것

호감도를 올리기 위한 반복 선물, 행동력 소모, 매일 접속 보상, 답장 제한 시간, 랜덤 육아 문제, 모든 데이트의 별도 미니게임은 제안하지 않는다. 이미 작성된 고유 활동과 감정 흐름을 끊거나 새 그림·테스트 비용을 늘릴 가능성이 크다. 먼저 한 루트에서 CG 전환과 기록집이 실제로 만족스러운지 읽기 테스트로 확인한다.

## 이번에 완료한 범위

서윤 설정·대사·관계 계산·기록 제목·네이티브 테스트 기대값·제작 목록을 맞췄다. 위 시스템 제안의 신규 UI나 게임 규칙은 아직 구현하지 않았다. 실제 엔진 실행과 플레이어 재미 검증은 미완료다.
