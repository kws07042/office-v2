## 변경 결과

투명 대화창을 유지하면서 이름·본문·진행 표시와 하단 빠른 메뉴의 간격을 정리했다. 본문은 Pretendard 26px, 이름은 GowunDodum 23px이며 기존 화자별 색을 유지한다. 배경과 입상은 기존 파일을 그대로 사용한다.

사용자 요청에 따라 일반 선택지는 **화면 가로 중앙**에 세로로 배치한다. 1280×720 기준 폭 600px, 하단 기준 y=486이며 대화 본문보다 위에 놓인다. 긴 문장은 중앙 스크롤 영역으로, 4개 이상 선택지는 기존 큰 중앙 패널 안의 스크롤 목록으로 표시한다. 캡션·행동·결과는 변경하지 않는다.

메신저는 크림·라벤더 색, 작은 모서리 곡률, 차분한 글자색으로 통일했다. 왼쪽 연락처와 오른쪽 대화 영역을 구분하고 본문과 답장의 스크롤을 분리했다. 기본 답장 세 개는 한 번에 표시하며 긴 답장만 스크롤한다. 연락처 전환, 진행 중인 대화 복귀, 기다림, 사진 확대와 빈 상태를 유지한다. 진행 기록 메뉴를 열었을 때도 일반 HUD가 겹쳐 나오지 않도록 했다.

## 파일

- `Source/game/office_ui.rpy`: 공통 패널·선택지·스크롤바 스타일.
- `Source/game/screens.rpy`: 대화창, 중앙 선택지, 빠른 메뉴 간격.
- `Source/game/office_phone.rpy`: 메신저 화면과 스타일.
- `Source/game/cream_ui.rpy`: 기록 메뉴를 포함하는 HUD 표시 조건.
- `Preview/office-dialogue-phone-v001.html`, `.css`, `.js`: 독립 브라우저 미리보기.
- `Docs/ui-dialogue-phone-v001-qa.json`: 확인 결과와 한계.

미리보기는 저장·분기와 연결되지 않는다. 기존 게임 원문을 사용하고, 다른 세 연락처에는 임의의 대사를 만들지 않았다. ‘긴 문장’은 넘침 확인용으로 기존 문구를 반복한다. 저장·설정 등 미리보기 버튼은 설명 창을 열며 실제 게임 기능을 흉내 내어 저장하지 않는다. 실제 Ren’Py의 원래 액션은 유지한다.

## 확인한 내용

- 브라우저 1280×720 논리 좌표에서 선택지 중심 오차 **0px**, 본문과 분리.
- 낮·저녁, 긴 문장, 기본 답장 3개 표시와 긴 답장 스크롤.
- 연락처 전환 및 복귀, 세 번째 답장 Enter 입력, 발송 후 답장 목록 제거.
- 발송 전 4개 → 내 답장 후 5개 → 상대 응답 후 6개. 중복 추가 없음.
- 대화 기록, 사진 준비 중 표시와 Escape 닫기.
- 브라우저 콘솔 오류 0개, 페이지 가로 넘침 없음.
- 미리보기 JavaScript 문법 확인.
- RPY의 Python 블록 5개를 AST로 구문 확인만 수행.
- 메신저 기본값·데이터 함수는 주석·공백을 제외하고 동일, `label phone_deliver` 이후 시나리오는 정확히 동일.
- 기존 진행 모델 테스트 **38개 통과**.

## 아직 확인하지 못한 내용

로컬 Ren’Py SDK가 없어 실제 화면 언어 파싱·폰트 줄바꿈·버튼 포커스와 저장/불러오기/롤백/Replay는 실행하지 않았다. 브라우저 미리보기는 실제 엔진 캡처가 아니며 시스템 글꼴을 사용하므로 게임의 번들 Pretendard/GowunDodum과 줄바꿈이 조금 다를 수 있다. 예시 그림은 기존 게임 입상이며 새 일러스트가 아니다.

병합 전 공식 SDK에서 다음을 확인한다.

- [ ] Lint 및 정상 시작, 기존 저장 파일 불러오기.
- [ ] ‘화면 배치 확인’에서 낮·밤·일반/긴 선택지·키보드 포커스.
- [ ] R08 메신저 세 답장 분기, 긴 기록 스크롤, 연락처 전환과 사진 닫기.
- [ ] 메신저 도중 저장·불러오기·롤백 시 중복 메시지와 답장 누락 없음.
- [ ] 선택지·메신저·기록 메뉴가 일반 HUD와 겹치지 않음.
- [ ] 다른 운영체제와 작은 창에서 글자 잘림·빠른 메뉴 충돌 없음.

오늘 작업은 UI 검토 브랜치 업로드까지이며 main 병합은 포함하지 않는다.
