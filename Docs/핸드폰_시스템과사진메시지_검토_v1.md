- 유진: 정리된 설명과 본인이 고른 추천·사진. 수줍어도 먼저 제안하고 도현의 감상에 자기 의견으로 답함.
- 서윤: 농담과 직접적인 보고 싶다는 표현·구체적인 만남 날짜. 중요한 약속을 농담만으로 끝내지 않는다.

## 4. 사진·기록의 상태와 제작량

메시지별 인물·사건·내용·수신 여부·읽음 여부·답장·첨부 자산·확대 열람 여부를 구분한다. 아직 받지 않은 사진을 현재 채팅의 기록에 표시하지 않는다. 과거 회상이나 다른 루트에서 받은 사진이 현재 회차의 관계 상태를 바꾸지 않아야 한다. 영구 갤러리 해금과 현재 회차의 수신 사진 목록은 분리한다.

썸네일은 원본 비율을 유지하고, 클릭 확대 뒤에는 같은 대화 위치로 돌아간다. 사진을 보다가 저장·되돌리기·스킵해도 메시지·기억·호감도 결과를 중복 적용하지 않는다. 축소 이미지와 원본을 같은 자산 ID로 연결하고 한국어 줄바꿈·사진 가림·버튼 위치를 720p와 1080p에서 확인한다.

일반 CG 18개는 기존 확정 수다. 사용자 답변으로 휴대폰용 일반 사진은 인물당 2장·총 8장으로 확정했다. 추가 요청 인물당 3장·총 12장은 사용자 제공 자산의 빈 예약 항목으로 수량만 관리한다. 두 분류는 일반 CG 18개와 별개이며 상세 수량은 7절을 따른다. 이전 리아 이미지는 재사용하지 않고 사용자 제작본을 기다린다. 지금 실제 사진 생성·편집은 하지 않는다.

## 5. 도입 전 실행 검증과 남은 결정

첫 시험은 일반 텍스트 몇 줄·답장 두 가지·비노골적인 임시 사진 한 장·확대·저장 후 복원으로 구성한다. 공개 전/후, 교제 전/후, 사진 미수신/수신, 미읽음/읽음, 되돌리기·회상·빠른 스킵을 확인한다. 음성 없는 메신저가 기본이며 빈 음성 재생 버튼을 붙이지 않는다. 본 검토는 실행 계획이며 실제 시험을 완료한 것은 아니다.

Q23은 이야기 중 중요한 대화를 자동으로 보여주고 읽기·답장 뒤 진행하는 방향으로 확정했다. 상세 흐름은 6절, 사진의 확정 수량과 예약 항목은 7절을 따른다. 일반 사진의 구체적인 파일·최종 대본과 추가 사용자 제공 자산은 아직 준비되지 않았다. 기본 기능의 완성도를 확보한 뒤 홈 화면·독립 앨범의 필요성을 판단한다.

## 6. 자동 대화 표시와 실제 진행 기록

사용자 확정: 중요 대화는 이야기 중 자동 표시한다. 진행 순서는 기존 사건의 메시지 계기 → 해당 채팅 표시 → 실제 메시지 읽기 진행 → 필요한 답장 선택 → 상대 반응 → 기존 본편 합류다. 휴대폰을 직접 찾아 열지 않았다는 이유로 다음 사건이나 필수 정보를 놓치지 않는다. 실제 응답 시간·접속 시간으로 벌점을 주지 않는다.

화면을 여는 것은 읽음·답장을 자동 처리하는 동작이 아니다. 실제 표시한 메시지를 진행했을 때 해당 읽기 상태를 기록하고, 답장 선택을 실제 전송하는 시점에 결과·기억을 한 번 적용한다. 선택을 확정하기 전에는 기존 미리보기·취소 기준을 따르고, 확정 이후 변경은 저장·되돌리기 상태 복원으로 처리한다.

현재 대화 중 과거 기록·사진 확대를 열면 현재 진행 위치를 보존한다. 확대를 닫으면 원래 채팅 위치로 돌아가며, 과거 기록을 닫으면 진행 중인 대화로 돌아간다. 필요한 답장을 아직 고르지 않았으면 채팅을 닫는 동작만으로 본편을 진행하거나 기본 답장을 대신 보내지 않는다. 다시 돌아와 같은 위치에서 선택할 수 있게 한다.

기록 열람에서는 과거 대사·실제로 받은 첨부를 보여주며 답장을 다시 전송하는 버튼을 붙이지 않는다. 다른 답장을 보고 싶은 경우 기존 회상·저장 복원 기능을 사용하고 현재 회차의 수치·기억과 섞지 않는다. 자동 대화 재진입·사진 반복 열람으로 호감도·수신 수·공개 인지 상태를 중복 적용하지 않는다.

사진 확대는 선택적이다. 진행에 필요한 장소·약속·관계 정보는 대사·캡션에도 있어서 사진을 확대하지 않아도 이해할 수 있어야 한다. 사진의 세부 내용을 실제로 본 것을 전제로 하는 반응은 확대 기록을 확인하거나 질문·일반 반응으로 대체한다. 별도 독립 앨범은 만들지 않고 기존 채팅 기록에서 다시 연다.

시험 항목은 메시지 직전 저장 후 복원, 답장 전 기록 열람과 복귀, 사진 확대 중 닫기·저장, 답장 뒤 되돌리기, 과거 기록 재열람, 빠른 클릭·스킵, 현재 회차와 영구 갤러리 상태 분리다. 실제 시험은 아직 진행하지 않았다.

## 7. 메시지 사진 8장과 사용자 제공 자산 예약 12개

사용자는 세 번째 선택지인 일반 사진 인물당 2장·총 8장을 선택하고, 별도로 노골적인 사진 인물당 3장·총 12장을 요청했다. 여기서는 일반 사진의 제작량과 일반적인 자산 관리만 설계한다. 노골적인 사진의 내용·구도·성적 연출·생성 지침은 작성하지 않는다. 추가 요청 수량은 사용자 제공 자산의 내용 없는 예약 칸으로 기록한다.

일반 CG 18개를 더하면 이 세 분류는 총 38개의 계획·예약 항목이다. 입상·배경·본편의 다른 이미지 전체를 포함한 수가 아니며 완성 파일 수도 아니다. 사건 95개·일반 CG 18개를 유지하고 이번 작업에서 사진 생성·편집·업스케일·기존 리아 이미지 연결은 하지 않는다.

## 8. 공통 UI 스타일 연결

통합 기획서 v2.35의 44절과 UI 오피스·모에 스타일 명세를 따른다. 연락처 이름·짧은 알림은 부드러운 고운돋움, 메시지 본문·답장·시간·기록은 읽기 좋은 Pretendard를 시작 후보로 둔다. 단정한 정보 배치에 둥근 말풍선과 작은 포인트를 더한다. 실제 게임의 글꼴 파일·최종 크기·저장/입력 검증은 아직 미완료다.

오피스 라운드 배치는 사용자 확정이다. PC에서는 연락처와 현재 대화를 나란히 보여주고 좁은 폭은 연락처를 상단에 옮긴다. 현재 대화 자동 표시·기록 복귀·사진 확대의 기존 규칙은 그대로 유지한다.

## 9. 상대 입력 중 표시 — 의미 있는 답장만

사용자는 고백·중요한 약속·진심을 말하는 의미 있는 답장에만 잠깐 사용하는 것으로 확정했다. 일반 연락·평범한 정보·짧은 확인에는 입력 대기를 넣지 않는다. 제안 시간은 의미 있는 말 1~1.5초, 한 번의 상한 2초이며 사용자 확정 시간·측정 결과는 아니다. 연속 메시지 묶음 앞에 한 번만 쓰고 모든 줄 앞에 반복하지 않는다. 실제 대본의 각 메시지에 표시 사용 여부·장면 목적을 명시한다.

| 인물 | 어울리는 변화 | 피할 반복 |
|---|---|---|
| 리아 | 평소의 빠른 장난 뒤 진심을 말할 때 잠깐 멈춤 | 모든 장난마다 기다리게 하기 |
| 지현 | 평소 답장은 바로 표시하고 중요한 사적 부탁 전에는 짧게 멈춤 | 일을 못 하거나 결정을 못 내리는 인상으로 바꾸기 |
| 유진 | 먼저 제안하는 메시지의 작은 긴장 | 수줍음을 이유로 모든 답장을 느리게 만들기 |
| 서윤 | 농담과 직접적인 약속을 말하는 순간의 속도 차이 | 중요한 마음을 매번 쓰다 지우는 연출로 피하기 |

입력 중 표시 뒤에는 완성된 말풍선을 보여준다. 입력 대기와 글자별 출력 대기를 겹치지 않는다. 클릭·스킵·효과 줄이기 설정으로 대기를 생략해도 같은 메시지·선택·기억에 도달한다. 실제 접속·응답 속도로 호감도·결말을 바꾸지 않는다.

미전송 초안을 고르는 연출과 실제 보낸 메시지를 삭제한 사건은 구분한다. 단지 입력 중 표시가 사라졌다고 채팅 기록에 ‘삭제된 메시지’나 과거 내용을 생성하지 않는다. 실제 메시지가 도착하기 전에는 본문·읽음·사진 수신을 먼저 기록하지 않는다.

저장·복원·되돌리기에서는 표시 중인 단계·예정된 메시지를 복원하고 무한 대기·중복 수신을 막아야 한다. 다른 연락처·기록·사진을 열 때 지연된 반응이 잘못된 인물에게 붙지 않게 한다. 작성 중 표시 자체는 점수·사건 결과를 적용하지 않는다. 미리보기의 짧은 표시와 실제 Ren’Py 구현·검증은 구분한다.

## 10. 선택 루트와 나머지 연락처의 새 대화

사용자 확정: 한 루트를 고른 뒤에는 그 히로인의 개인 대화에 집중하고, 다른 세 명의 새 연락은 업무·공통 모임에 한정한다. 교제 공개에 따른 짧은 축하는 기존 공통 사건 반응으로 유지한다. 다른 히로인의 별도 일상 안부 가지를 추가하지 않는다.

| 단계 | 새 연락 범위 | 유지할 기록 |

| 공통 C08 이전 | 기존 소개·C06·C07의 실제 대화 | 실제로 나눈 인물별 이야기와 약속 |

현재 UI 미리보기의 네 연락처와 샘플 답장은 배치·글꼴·입력 중 동작을 설명하는 예시다. 실제 게임의 루트별 메시지 필터를 구현한 결과는 아니며 이 규칙은 Ren’Py 구현에서 따로 검증한다. 연락처를 눌렀다는 이유로 활성 연애 루트가 바뀌거나 미수신 메시지가 도착하지 않아야 한다.

통합 기획서 v2.40 기준으로 도현 이름은 고정이다. 개인·업무 채팅의 호칭은 실제 인물·상황·관계 단계와 일치시키고, 이름 입력·변경 또는 플레이어 이름에 따른 음성 생성 기능을 추가하지 않는다.

## 11. 빠른 새 회차 시작의 채팅 초기 상태

통합 기획서 v2.42의 14절을 따른다. 공통 C08 완료 후 첫 엔딩 전에도 새 회차를 빠르게 시작할 수 있다. 연락처 선택으로 현재 관계를 전환하지 않고 별도 새 시작 메뉴를 사용한다. 현재 저장을 보존하고 선택한 공통 경로의 기록으로 새 채팅 상태를 구성한다.

기존 공통 기록을 재사용하면 그 경로의 실제 수신·답장을 복원한다. 공통 선택을 새로 구성하면 확정한 요약 사실과 실제 표시·전송한 메시지만 기록하고 보지 않은 원본 대화 전체를 생성하지 않는다. 이전 루트의 교제 후 대화·사적 사진 수신·읽음·공개 상대의 인지 상태·미전송 답장·입력 중 타이머는 가져오지 않는다. 영구 갤러리의 해금은 현재 채팅의 수신을 대신하지 않는다. 새 상대의 R01부터 해당 루트의 연락을 진행한다. 실제 구현·실행 검증은 아직 하지 않았다.

통합 기획서 v2.43 기준으로 미확인 C06·C07 만남은 핵심 대화도 보여주고 읽은 부분만 요약한다. 핵심 부분에 실제 메시지 송수신이 포함되면 해당 대화만 현재 기록에 넣고 생략한 원본 전체를 채팅으로 만들어 넣지 않는다. 요약에서 얻은 취향·약속을 채팅으로 들었다고 바꾸지 않는다. 실제 보여준 대사·송수신 상태·확정한 공통 사실은 서로 구분해 관리한다.

통합 기획서 v2.45의 히로인 단독 시점에서 보여준 미전송 메시지·혼자 고른 날짜는 도현 휴대폰의 수신·읽음·알림·약속으로 기록하지 않는다. 상대 입력 중 표시도 도현이 실제로 보고 있는 채팅 상황에서만 사용한다. 실제 전송·전달 장면이 발생한 뒤에만 해당 메시지와 정보를 현재 기록에 반영한다. 단독 시점의 연출을 재열람해도 메시지를 다시 보내거나 관계 결과를 적용하지 않는다.

음악 연결은 통합 기획서 v2.49의 15절을 따른다. 메신저·사진 확대·기록 열람은 현재 이야기의 음악을 유지하며 창 열기·입력 중 표시·답장 버튼 때문에 곡을 다시 시작하지 않는다. 실제 감정·장소 변화가 있는 대화만 별도 전환을 지정한다. 이는 Ren’Py 음향 명세이며 현재 브라우저 미리보기에 음악을 추가하거나 실제 음원을 재생한 것은 아니다.

클라우드 연결은 통합 기획서 v2.57의 22절을 따른다. 검증 후 첫 출시 포함 목표이며 다른 PC에서도 저장한 회차의 실제 메시지 진행·답장·수신·사진 열람 기록을 복원해야 한다. 영구 갤러리에서 열린 다른 회차의 사진을 현재 연락처에 자동 수신시키지 않는다. 저장 충돌은 해당 회차의 상태 전체를 기준으로 확인하고 인물별 대화 조각을 서로 다른 진행에서 임의로 합치지 않는다. 실제 파일 구조·Steam 설정·PC 간 동기화 시험은 아직 미완료다.
