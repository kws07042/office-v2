# 챗지피티 대사 교정 반복 프롬프트 v001 ("완벽할 때까지")

## 왜 바꿨나

지난 두 번은 고친 파일을 통째로 받았다. 그런데 줄을 넣고 빼거나, 도현의 반말을 존댓말로 바꾸는 일이 많아서 절반 넘게 버려야 했다.

이번에는 **바꿀 줄만 '줄 번호 + 원문 + 새 문장' 목록으로** 받는다. Claude가 자동으로 점검해서 맞는 줄만 넣고, 틀린 줄은 이유를 붙인 **반려 목록**으로 돌려준다. 그 반려 목록을 챗지피티에 다시 넣는 식으로, 반려가 0이 될 때까지 반복한다.

## 순서

1. 챗지피티 새 대화에 아래 **[1차 프롬프트]**와 `.rpy` 파일 하나를 넣는다(한 번에 한 파일).
2. 챗지피티가 준 JSON을 파일 이름과 함께 Claude에게 준다. 붙여 넣거나 `.json`으로 올리면 된다.
3. Claude가 점검해서 통과한 줄은 게임에 넣고, 남은 줄은 **반려 목록**으로 돌려준다.
4. 같은 챗지피티 대화에 **[2차 이후 프롬프트]**와 반려 목록을 넣는다.
5. 반려가 0이 되면 그 파일은 끝이다. 다음 파일로 넘어간다.

## [1차 프롬프트]

```text
너는 한국어 성인 연애 비주얼노벨 〈퇴근 후, 우리〉의 대사 교정자다. 첨부한 Ren'Py 대본에서 '사람이 쓴 것처럼' 고칠 줄만 골라, 아래 JSON 형식으로만 답해라. 파일 전체를 다시 쓰지 마라.

【출력 형식 — 이것만 출력】
[
  {"line": 줄번호(1부터), "old": "그 줄 전체 원문 그대로", "new": "고친 그 줄 전체"},
  ...
]
- "old"는 그 줄을 한 글자도 바꾸지 않고, 앞의 들여쓰기 공백까지 그대로 적는다.
- "new"도 한 줄 전체다. 들여쓰기 공백, 앞의 화자 표시(r, d, j, y, s, dn), 따옴표 구조를 원문과 똑같이 둔다.
- 줄을 새로 넣거나 지우지 않는다. 한 줄은 한 줄로만 바꾼다.

【고쳐도 되는 줄】
- 대사 줄: 화자 "..."  (예: j "...", d "...", dn "...")
- 지문 줄: "..."  (따옴표만 있는 줄)
- 문자 줄: call phone_deliver("ID", "보낸사람", "내용", ...) 의 '내용' 부분만

【절대 건드리지 말 것】
- label, menu, 선택지 줄("...":), if/elif/else, $로 시작하는 줄, call/jump/return, remember(...), award_once(...), phone_deliver의 ID와 보낸 사람.
- [ri('A','B')]가 있는 줄: A는 반말, B는 존댓말이다. 둘 다 고쳐도 되지만 A는 반드시 반말, B는 반드시 존댓말로 남긴다. ri가 없던 줄에 ri를 넣거나, 있던 ri를 없애지 마라.
- ri가 없는 도현(d) 줄은 원래가 반말이면 반말, 존댓말이면 존댓말 그대로.
- '도현'이라는 글자 수를 바꾸지 마라(늘리지도 줄이지도). 조사는 도현이·도현은·도현을·도현과·도현아·도현으로·도현이었·도현 씨만.
- 지문은 3인칭이다. '나/내/내가'로 쓰지 마라(dn 속마음 줄만 1인칭 가능).
- 이모지 금지. 대괄호 [ ]와 중괄호 { }를 새로 쓰지 마라.
- 일어난 사실(시간, 장소, 옷, 약속, 누가 무엇을 했는지)과 인물 관계를 바꾸지 마라.

【인물 버릇 — 지켜야 할 것】
- 리아: 밝고 빠른 말끝, 장난, ~·!. 결정적인 순간엔 말이 짧아진다.
- 지현: 짧고 결론부터. 버릇인 '결론부터 말할게'는 남긴다. 칭찬엔 "...그런 건" 하고 말을 잃는다.
- 유진: 존댓말, 말끝을 흐리다 직구. 색·빛·그림 이야기.
- 서윤: 여유로운 반말로 떠보다 진심일 땐 장난을 멈춘다. 이혼(자녀 없음).
- 도현: 다정하고 차분.

【사람이 쓴 것처럼】
1. 실제로 말하는 길이와 리듬. 끊고, 되묻고, 피하기도 한다.
2. 감정을 이름으로 말하지 않는다('설렜다', '마음이 따뜻해졌다' 금지). 행동과 사물로 보여 준다.
3. 결론을 대사로 정리하지 않는다. 서로를 설명해 주는 대사 금지.
4. AI 티 나는 표현 금지: 왠지 모르게, 문득, 살며시, 조심스럽게, 어느새, 그 순간, 진심으로, 소중한, 특별한, 함께라서, '마치 ~처럼'의 남발, 줄표(—)로 잇기, 셋씩 나열하기.
5. 이미 자연스러운 줄은 고치지 마라. 고칠 필요가 있는 줄만 고른다(보통 파일의 10~30%).

【제출 전에 스스로 점검】
줄마다 확인하고, 하나라도 걸리면 그 줄을 빼거나 고친 뒤 제출해라.
- old가 원문과 정확히 같은가?
- 화자 표시와 들여쓰기가 같은가?
- ri의 A는 반말, B는 존댓말인가?
- '도현' 글자 수가 같은가?
- 지문이 3인칭인가?
- 이모지·대괄호·중괄호를 새로 쓰지 않았나?
JSON만 출력하고 다른 말은 쓰지 마라.
```

## [2차 이후 프롬프트] (Claude가 준 반려 목록과 함께)

```text
아래는 네가 낸 교정안 중 반려된 줄과 그 이유다. 이유를 고쳐서 같은 JSON 형식으로 그 줄들만 다시 내라.
반려 이유를 고칠 수 없으면 그 줄은 빼라(원문 유지). 이미 통과한 줄은 다시 내지 마라.
규칙은 1차 프롬프트와 같다. JSON만 출력해라.

[반려 목록]
(여기에 Claude가 준 목록 붙여 넣기)
```

## 반려 이유 코드

반려 목록에 아래 코드가 붙어 나간다.

| 코드 | 뜻 |
|---|---|
| OLD_MISMATCH | old가 원문과 다름(줄 번호나 글자) |
| CODE_LINE | 고치면 안 되는 코드·선택지 줄 |
| SPEAKER | 화자 표시나 들여쓰기가 바뀜 |
| RI_FORMAT | ri를 넣거나 뺌, 괄호 형식이 깨짐 |
| REGISTER | ri의 반말 쪽이 존댓말이 되었거나 그 반대, 또는 도현 말투 변경 |
| NAME | '도현' 글자 수가 바뀜 또는 허용 안 된 조사 |
| FIRST_PERSON | 지문이 1인칭이 됨 |
| EMOJI | 이모지·대괄호·중괄호 |
| TEST | 게임 테스트가 확인하는 문장이라 못 바꿈 |
| HABIT | 인물 버릇이 빠짐(예: 지현의 '결론부터') |
